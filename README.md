# HackAlem — модуль 1: данные и подбор подрядчиков

Модуль читает CSV, сверяет его с HTML-превью, сохраняет единый JSON и подбирает
до трёх кандидатов с фактами для объяснений и причинами исключения остальных.

## Проверенные данные

Предоставлены CSV и HTML, а не Excel. Оригиналы сохранены в `data/source/`.
В каждом источнике **66 профилей**, наборы `id` совпадают. Расхождений в
сопоставимых полях не найдено. HTML содержит сокращённые описания и количества
занятых дней вместо конкретных дат. Описания проверяются как полный текст или
префикс, количества дней — по календарю CSV. Полное совпадение календарей по
HTML установить нельзя.

Источник единого JSON — CSV; объединения записей нет.
Отчёт: `data/comparison.json`. Данные: `data/profiles.json`.
Период календаря из HTML: **2026-09-23 — 2026-12-31** включительно.
За его пределами профиль исключается с кодом `date_outside_calendar`:
доступность неизвестна.

## Запуск

Python 3.9 или новее, только стандартная библиотека. API-ключи не нужны.
Команды выполняются из корня проекта:

```bash
python3 ingest.py data/source/profiles.csv data/source/preview.html
python3 matching.py data/profiles.json examples/dataset_request.json
python3 -m unittest discover -s tests -v
```

Импорт при расхождениях записывает отчёт и завершается с ошибкой, не записывая
новый `profiles.json`. Старый файл остаётся: использовать его как результат
неуспешного импорта нельзя. Папка результата задаётся через `--output-dir`.

## Пример проверки для жюри

Запрос `examples/dataset_request.json`: ведущий в Алматы на свадьбу
10 октября 2026 года, бюджет 1 000 000 KZT, русский язык, 5 часов.
Проходят два профиля: `HK-27222` (Сон Гоку) и `HK-77838` (Хаул),
у обоих цена от 1 000 000 KZT. Порядок определяется `id`.
Полный ответ: `data/example_result.json`. Остальные 64 профиля имеют причины отсева.

Независимый пример на вымышленных данных:

```bash
python3 matching.py examples/profiles.json examples/request.json
```

## Правила подбора

1. Нормализация чисел, списков, дат и флагов; проверка дубликатов `id`.
2. Фильтры: город → категория → дата → бюджет → формат → язык → длительность.
3. Ранжирование прошедших кандидатов по меньшей указанной цене.
4. До трёх результатов и причины исключения остальных, включая `outside_top_3`.

Возвращаются все нарушенные условия. Балл: `100 * (budget - price) / budget`.
При нулевом бюджете проходят только бесплатные профили с баллом 100.
При равенстве баллов сортировка по строковому `id`. Балл отражает остаток
бюджета, а не качество подрядчика.

## Схема и допущения

| Колонка CSV | Нормализованное значение |
| --- | --- |
| `id` | строковый идентификатор |
| `anon_name` | `name` |
| `categories`, `languages` | массивы |
| `city` | город в нижнем регистре без лишних пробелов |
| `event_formats` | массив `formats`: свадьба, корпоратив и т. д. |
| `price_from_kzt` | число `price`, `price_kind: starting`, валюта KZT |
| `busy_dates` | массив занятых дат `YYYY-MM-DD` |
| `max_hours` | число или `null` |
| `city_imputed`, `price_imputed`, `synthetic` | логические значения |
| `description` | исходный текст |

Списки принимаются как массивы, JSON-строки массивов или строки с разделителями
`|`, `;`, `,`, переносом строки. Даты: `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY`.
Цены могут содержать пробелы и десятичную запятую. Неизвестные поля не сохраняются.

- `max_hours: null` означает отсутствие ограничения по присутствию. Пустая ячейка
  CSV трактуется так же; HTML отображает её как «не применимо».
- Отсутствие даты в `busy_dates` означает отсутствие записи о занятости,
  а не подтверждение бронирования; это отражено в `availability_basis`.
- Начальная или восстановленная цена требует уточнения:
  `price_requires_confirmation: true`. Бюджет проверяется по цене «от».
- Флаги восстановленных значений и синтетических профилей передаются в фактах,
  сами по себе они не исключают кандидата.
- Строки сопоставляются без учёта регистра. Синонимы не распознаются.

Поддерживается и схема вымышленного примера: `name`, `price`, `formats`,
`available_dates`. Если указан список свободных дат, дата должна быть в нём
и отсутствовать среди занятых. Пустой `busy_dates` — пустой список;
`null` для него не принимается. Отсутствующий `max_hours` — ошибка.

## Подключение к API команды

```python
import json
from pathlib import Path
from matching import select_candidates

profiles = json.loads(Path('data/profiles.json').read_text(encoding='utf-8'))
request = {
    'city': 'Алматы', 'category': 'Ведущий', 'date': '2026-10-10',
    'budget': 1000000, 'format': 'свадьба',
    'language': 'русский', 'duration_hours': 5,
}
result = select_candidates(profiles, request)
```

Обязательны `city`, `category`, `date`, `budget`, `format`.
`language` и `duration_hours` можно пропустить или передать `null`.

Ответ содержит:

- `candidates`: `profile`, `score`, `facts` — условия запроса, остаток бюджета по
  указанной цене, основание оценки доступности и флаги данных.
- `rejected`: `id`, массив `reasons` с кодом, полем, условием запроса и значением
  профиля. Для `outside_top_3` — место и балл.
- `total`, `eligible_count`, `ranking_rule`.

Ошибочные данные вызывают `ValueError`; отсутствующие поля запроса — `KeyError`.
HTTP-обработчик команды должен преобразовать исключения в ошибку запроса.

## Архитектура и проверки

- `ingest.py`: CSV → нормализация; разбор HTML → сверка → JSON.
  HTML и JavaScript не выполняются.
- `matching.py`: нормализация, подбор, CLI и сравнение полных записей
  (`compare_sources`). Сокращённый HTML сверяется отдельно через `ingest.prepare`.
- `tests/`: фильтры, границы бюджета и длительности, `null`, стабильность порядка,
  ошибочные данные, сверка настоящих файлов, обнаружение изменения цены,
  повторная нормализация и границы календаря.

## Ограничения и внешние сервисы

Чтение XLSX не реализовано: предоставлен CSV. HTML-парсер предназначен для
структуры данного превью. Почасовые тарифы, конвертация валют, бронирование,
HTTP API и интерфейс отсутствуют. Бюджет считается указанным в KZT.
Истинность описаний не проверяется; они сохраняются как данные и не управляют
алгоритмом. Внешние API и AI-модели при подборе не вызываются.
Развёрнутой версии нет.
